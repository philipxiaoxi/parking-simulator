# 停车训练驾驶模拟器 MVP 开发任务拆解

## 1. 文档信息

- 文档名称：MVP 开发任务拆解
- 关联文档：
  - `PRD.md`
  - `Web技术架构设计草案.md`
- 文档版本：v0.1
- 文档日期：2026-04-17
- 文档用途：用于指导 Web MVP 的开发排期、模块拆分与验收

## 2. 拆解原则

本拆解遵循以下原则：

- 先验证核心训练闭环，再扩展编辑能力
- 先做稳定的规则与交互，再补视觉细节
- 尽量降低模块耦合，方便多人协作
- 所有任务围绕 MVP 范围，不提前实现增强项

MVP 的最小完成定义为：

- 用户可创建并保存地图
- 用户可在地图中放置障碍物、车位框、判定线和出生点
- 用户可切换到驾驶模式操作车辆
- 车辆碰撞后会失败并可重置
- 车辆四轮进入车位框时成功
- 车辆车头越过判定线时成功
- 地图列表可再次加载并训练

## 3. 总体阶段划分

建议按 6 个阶段推进：

1. 项目初始化与技术骨架
2. 3D 场景与车辆基础能力
3. 训练闭环与规则判定
4. 地图编辑器 MVP
5. 地图存储与列表管理
6. 体验收尾与 MVP 验收

## 4. 任务全景图

```text
阶段 1: 项目初始化
  ↓
阶段 2: 车辆可动 + 场景可见
  ↓

  ↓

  ↓
```

## 5. 详细任务拆解

## 5.1 第一阶段：项目初始化与技术骨架

目标：

- 搭建可运行的 Web 工程
- 确立基础目录结构
- 验证 React、R3F、Rapier、Zustand 可协同工作

任务列表：

- 初始化 Vite + React + TypeScript 项目
- 安装并接入 React Three Fiber
- 安装并接入 drei
- 安装并接入 Rapier
- 安装并接入 Zustand
- 建立基础目录结构
- 建立基础类型目录与共享常量目录
- 建立基础页面路由
- 建立基础样式方案

交付物：

- 可运行的前端工程
- 初始页面骨架
- 空白 3D 画布页面

验收标准：

- 本地可启动项目
- 页面能正常渲染
- 3D Canvas 成功显示
- 全局状态管理已接入

依赖关系：

- 无前置依赖

## 5.2 第二阶段：3D 场景与车辆基础能力

目标：

- 在浏览器中看到基础训练场景
- 实现车辆的低速运动和相机控制

任务列表：

- 创建基础地面与世界坐标参考
- 实现默认斜俯视相机
- 实现相机拖拽、缩放、旋转
- 创建基础车辆 3D 表现
- 抽象车辆几何参数
- 实现车辆状态结构
- 实现键盘输入采集
- 实现前进、后退、左转、右转基础输入
- 实现简化低速运动模型
- 实现车辆位置、朝向实时更新
- 实现车辆重置到出生点

交付物：

- 可驾驶车辆
- 可操作相机
- 基础场景地面

验收标准：

- 用户可通过键盘控制车辆前进后退和转向
- 相机能够覆盖整个训练区域
- 车辆可稳定重置到初始位置
- 车辆运动表现无明显抖动或失控

依赖关系：

- 依赖第一阶段完成

## 5.3 第三阶段：训练闭环与规则判定

目标：

- 建立“碰撞失败 / 达成目标成功”的核心玩法闭环

任务列表：

- 抽象障碍物碰撞体结构
- 在场景中渲染障碍物
- 接入障碍物碰撞检测
- 定义训练状态机
- 实现碰撞失败判定
- 实现失败提示
- 实现失败后重置逻辑
- 定义车位框目标对象结构
- 定义判定线目标对象结构
- 计算车辆四轮参考点
- 实现四轮入框成功判定
- 定义车辆车头参考点
- 实现车头过线成功判定
- 实现多成功目标并存逻辑
- 实现成功提示
- 实现成功后停止输入或进入完成状态

交付物：

- 完整训练闭环
- 基础成功失败 HUD

验收标准：

- 撞到障碍物后稳定进入失败状态
- 四轮进入车位框后稳定进入成功状态
- 车头越过判定线后稳定进入成功状态
- 同一地图存在多个成功目标时，任一目标满足即可成功
- 成功和失败状态不会重复触发或来回抖动

依赖关系：

- 依赖第二阶段完成

## 5.4 第四阶段：地图编辑器 MVP

目标：

- 用户能自己创建训练场景

任务列表：

- 建立编辑模式与驾驶模式切换
- 实现左侧编辑面板
- 实现摆件类型列表
- 实现地图中新增对象
- 实现对象选中
- 实现对象平面移动
- 实现对象旋转
- 实现对象删除
- 实现出生点放置与调整
- 实现车位框放置与调整
- 实现判定线放置与调整
- 实现基础网格吸附
- 实现编辑态与选中态高亮

MVP 明确不做：

- 多选编辑
- 自由缩放
- 复杂撤销重做
- 图层管理
- 批量操作

交付物：

- 可用地图编辑器

验收标准：

- 用户可在编辑模式下放置障碍物
- 用户可调整出生点、车位框、判定线的位置与朝向
- 切换到驾驶模式后可基于当前编辑结果立即试跑
- 编辑模式下不会误触发驾驶输入

依赖关系：

- 依赖第二阶段完成
- 第三阶段可并行推进，但最终要联调

## 5.5 第五阶段：地图存储与列表管理

目标：

- 地图可持久化保存与再次加载

任务列表：

- 定义地图 JSON 数据结构
- 定义地图版本号策略
- 实现地图元信息结构
- 实现地图列表读取
- 实现新建地图
- 实现地图重命名
- 实现地图删除
- 实现地图保存
- 实现地图再次加载
- 接入 localStorage 维护索引
- 接入 IndexedDB 存储地图内容
- 处理空地图默认初始化

交付物：

- 地图列表页
- 持久化读写模块

验收标准：

- 新建地图后可在列表中看到
- 编辑后的地图刷新页面后仍可重新加载
- 删除地图后列表同步更新
- 保存和读取不会破坏对象位置、朝向和规则配置

依赖关系：

- 可与第四阶段并行
- 最终联调依赖编辑器基础能力完成

## 5.6 第六阶段：体验收尾与 MVP 验收

目标：

- 让 MVP 从“能跑”变成“可演示、可体验”

任务列表：

- 完善地图工作台布局
- 完善顶部工具栏
- 完善底部 HUD
- 增加操作提示文案
- 增加状态提示文案
- 增加加载失败或空状态处理
- 增加基础调试开关
- 清理明显的 UI 阻塞问题
- 清理明显的交互误触问题
- 进行核心链路联调
- 完成 MVP 验收清单

交付物：

- 可演示版本 MVP

验收标准：

- 新用户能理解基本操作
- 地图创建、编辑、保存、训练链路完整可用
- 成功失败反馈清晰
- 没有阻塞性 bug

依赖关系：

- 依赖前五阶段基本完成

## 7. 推荐实施顺序

如果按“最短路径先验证玩法”来排，建议顺序如下：

1. 空白场景 + 相机
2. 车辆可动
3. 障碍物碰撞失败
4. 车位成功判定
5. 判定线成功判定
6. 重置与成功失败提示
7. 编辑模式基础能力
8. 地图保存和加载
9. 地图列表
10. 页面与体验收尾

这个顺序的优势是：

- 最早验证核心训练价值
- 避免一上来陷入编辑器细节
- 规则层先稳定，后续编辑器只是给规则喂数据

## 8. 里程碑建议

## 里程碑 M1：车辆能开

定义：

- 看得到地面
- 看得到车
- 相机可动
- 车辆可驾驶

## 里程碑 M2：训练可玩

定义：

- 有障碍物
- 能碰撞失败
- 能车位成功
- 能过线成功
- 能重置

## 里程碑 M3：地图可配

定义：

- 能放障碍物
- 能放出生点
- 能放车位框
- 能放判定线
- 切模式后可立即试跑

## 里程碑 M4：MVP 可演示

定义：

- 有地图列表
- 可保存加载
- UI 完整
- 训练闭环稳定

## 9. MVP 验收清单

以下清单全部通过，可认为 MVP 达标：

- 能创建至少一张新地图
- 能在地图中放置至少一种障碍物
- 能设置车辆出生点和朝向
- 能放置车位框
- 能放置判定线
- 能切换进入驾驶模式
- 能使用键盘控制车辆移动
- 撞到障碍物会失败
- 四轮进入车位框会成功
- 车头越过判定线会成功
- 成功或失败后可重置
- 地图可保存并在列表中再次打开

## 10. 风险最高的任务

从工程角度看，最容易卡住的不是列表页，而是以下四块：

- 车辆低速运动手感
- 四轮入框判定的几何稳定性
- 编辑模式中的对象交互
- 场景状态与 UI 状态同步

建议优先通过最小原型验证这四项。

- 多车型
- 触屏手柄优化
- 轨迹回放
- 教学辅助线
- 评分系统
- 社区地图

下一层最值得拆的文档是：

## 13. 结论

这份 MVP 开发任务拆解的核心思路是：

- 用最短路径先打通训练闭环
- 把“规则判定”放在“编辑器复杂度”之前
- 先证明产品成立，再逐步补完整工具链

如果后续进入实现模式，建议优先围绕里程碑 `M1 -> M2 -> M3 -> M4` 推进，而不是按页面或文件平均发力。
